## Agenda
Design Review: Adopt MongoDB for novacommerce-checkout database storage

## Discussion
The team discussed the problem: 'High read/write latency during peak traffic periods resulting in database connection pools exhausting, causing intermittent errors in downstream services.'. Author EMP-125 presented the proposal to: 'Migrate the primary storage of novacommerce-checkout to MongoDB to leverage its native scaling and high availability features.'. We reviewed alternatives: 1. Scale vertical resources on existing systems.
2. Implement a distributed cache layer (e.g. Redis) as a buffer.
3. Migrate to a multi-master distributed DB like MongoDB.. Feedback was mostly positive regarding the expected benefits: 'Reduced query latency by 50%, elimination of connection pool exhaustion incidents, and support for 5x current transaction volume.'. SRE raised concerns on potential risks: 'Complexity of live migration, operational overhead of maintaining clusters, and potential data format conversion issues during the transition.', which we decided to mitigate by scaling up monitoring.

## Decisions Made
Approved implementation of decision. EMP-125 to publish official ADR and create Jira implementation tasks.
