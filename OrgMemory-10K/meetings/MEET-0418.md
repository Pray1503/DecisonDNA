## Agenda
Design Review: Introduce AWS SQS for decoupled communications in visionai-pipeline

## Discussion
The team discussed the problem: 'Tight coupling leads to cascading failures across the backend. We need asynchronous messaging to guarantee eventual consistency and fault tolerance.'. Author EMP-019 presented the proposal to: 'Integrate AWS SQS to enable asynchronous, event-driven communication between visionai-pipeline and downstream microservices.'. We reviewed alternatives: 1. Keep synchronous REST APIs but increase timeouts and retry limits.
2. Introduce an HTTP webhook callback system.
3. Deploy AWS SQS as a centralized event broker.. Feedback was mostly positive regarding the expected benefits: 'Cascading failures are avoided; service availability increases to 99.99%; peak traffic load is smoothed.'. SRE raised concerns on potential risks: 'Introducing a single point of failure (event broker), message duplication, and increased complexity in tracing requests end-to-end.', which we decided to mitigate by scaling up monitoring.

## Decisions Made
Approved implementation of decision. EMP-019 to publish official ADR and create Jira implementation tasks.
