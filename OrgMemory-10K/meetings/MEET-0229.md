## Agenda
Design Review: Adopt MySQL for security-auth-proxy database storage

## Discussion
The team discussed the problem: 'High read/write latency during peak traffic periods resulting in database connection pools exhausting, causing intermittent errors in downstream services.'. Author EMP-175 presented the proposal to: 'Migrate the primary storage of security-auth-proxy to MySQL to leverage its native scaling and high availability features.'. We reviewed alternatives: 1. Scale vertical resources on existing systems.
2. Implement a distributed cache layer (e.g. Redis) as a buffer.
3. Migrate to a multi-master distributed DB like MySQL.. Feedback was mostly positive regarding the expected benefits: 'Reduced query latency by 50%, elimination of connection pool exhaustion incidents, and support for 5x current transaction volume.'. SRE raised concerns on potential risks: 'Complexity of live migration, operational overhead of maintaining clusters, and potential data format conversion issues during the transition.', which we decided to mitigate by scaling up monitoring.

## Decisions Made
Approved implementation of decision. EMP-175 to publish official ADR and create Jira implementation tasks.
