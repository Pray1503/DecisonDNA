# Incident Report: INC-0047 - Out of memory (OOM) crash in platform-logging pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0104
* **Linked PR:** PR-0066
* **Linked ADR:** ADR-0013

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (1Gi) and got OOMKilled.

## Incident Timeline
- **2021-03-07 10:27:00**: System Alert - Anomalous Metrics Detected
- **2021-03-07 10:30:00**: On-call Engineer Acknowledged Alert
- **2021-03-07 11:23:00**: Mitigation Applied - Increased pod count
- **2021-03-07 13:12:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 11:23:00 by rolling back production deployment DEP-0104 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
