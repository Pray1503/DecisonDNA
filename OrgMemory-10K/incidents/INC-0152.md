# Incident Report: INC-0152 - Cache stampede in fusionerp-payroll for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0320
* **Linked PR:** PR-0149
* **Linked ADR:** ADR-0037

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-06-26 04:22:00**: System Alert - Anomalous Metrics Detected
- **2021-06-26 04:37:00**: On-call Engineer Acknowledged Alert
- **2021-06-26 06:03:00**: Mitigation Applied - Rolled back deployment
- **2021-06-26 09:21:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 06:03:00 by rolling back production deployment DEP-0320 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
