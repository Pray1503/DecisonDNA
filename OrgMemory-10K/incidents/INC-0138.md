# Incident Report: INC-0138 - Cache stampede in insightcrm-analytics for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0291
* **Linked PR:** PR-0128
* **Linked ADR:** ADR-0030

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-06-05 03:25:00**: System Alert - Anomalous Metrics Detected
- **2021-06-05 03:38:00**: On-call Engineer Acknowledged Alert
- **2021-06-05 04:19:00**: Mitigation Applied - Rolled back deployment
- **2021-06-05 05:30:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 04:19:00 by rolling back production deployment DEP-0291 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
