# Incident Report: INC-0105 - Message lag spike on Kafka partition for visionai-training

* **Severity:** P1
* **Linked Deployment:** DEP-0220
* **Linked PR:** PR-0110
* **Linked ADR:** ADR-0024

## Root Cause Summary
A slow consumer thread due to synchronous downstream HTTP calls. As partition size grew, processing fell behind by over 50,000 messages, delaying order processing in NovaCommerce.

## Incident Timeline
- **2021-05-03 17:05:00**: System Alert - Anomalous Metrics Detected
- **2021-05-03 17:12:00**: On-call Engineer Acknowledged Alert
- **2021-05-03 17:52:00**: Mitigation Applied - Rolled back deployment
- **2021-05-03 20:17:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 17:52:00 by rolling back production deployment DEP-0220 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement worker pool concurrency in consumer code, wrap calls in circuit breakers, and monitor consumer lag metrics to trigger auto-scaling.
