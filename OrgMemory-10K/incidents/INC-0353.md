# Incident Report: INC-0353 - Cache stampede in visionai-inference for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0735
* **Linked PR:** PR-0366
* **Linked ADR:** ADR-0087

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-22 09:08:00**: System Alert - Anomalous Metrics Detected
- **2022-01-22 09:22:00**: On-call Engineer Acknowledged Alert
- **2022-01-22 10:24:00**: Mitigation Applied - Increased pod count
- **2022-01-22 13:26:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 10:24:00 by rolling back production deployment DEP-0735 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
