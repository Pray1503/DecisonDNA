# Incident Report: INC-0022 - Cache stampede in atlaspay-ledger for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0041
* **Linked PR:** PR-0006
* **Linked ADR:** ADR-0001

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-02-11 17:47:00**: System Alert - Anomalous Metrics Detected
- **2021-02-11 17:55:00**: On-call Engineer Acknowledged Alert
- **2021-02-11 18:28:00**: Mitigation Applied - Flushed cache
- **2021-02-11 22:20:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 18:28:00 by rolling back production deployment DEP-0041 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
