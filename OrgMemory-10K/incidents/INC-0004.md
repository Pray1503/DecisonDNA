# Incident Report: INC-0004 - Cache stampede in atlaspay-ledger for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0009
* **Linked PR:** PR-0004
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-01-21 13:52:00**: System Alert - Anomalous Metrics Detected
- **2021-01-21 13:59:00**: On-call Engineer Acknowledged Alert
- **2021-01-21 15:19:00**: Mitigation Applied - Increased pod count
- **2021-01-21 16:36:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 15:19:00 by rolling back production deployment DEP-0009 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
