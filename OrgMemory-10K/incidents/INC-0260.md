# Incident Report: INC-0260 - Out of memory (OOM) crash in security-auth-proxy pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0540
* **Linked PR:** PR-0270
* **Linked ADR:** ADR-0069

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (1Gi) and got OOMKilled.

## Incident Timeline
- **2021-10-31 20:11:00**: System Alert - Anomalous Metrics Detected
- **2021-10-31 20:18:00**: On-call Engineer Acknowledged Alert
- **2021-10-31 21:33:00**: Mitigation Applied - Flushed cache
- **2021-11-01 01:13:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 21:33:00 by rolling back production deployment DEP-0540 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
