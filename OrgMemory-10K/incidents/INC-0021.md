# Incident Report: INC-0021 - Out of memory (OOM) crash in security-auth-proxy pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0043
* **Linked PR:** PR-0027
* **Linked ADR:** ADR-0006

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-02-11 15:55:00**: System Alert - Anomalous Metrics Detected
- **2021-02-11 15:58:00**: On-call Engineer Acknowledged Alert
- **2021-02-11 17:22:00**: Mitigation Applied - Increased pod count
- **2021-02-11 20:45:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 17:22:00 by rolling back production deployment DEP-0043 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
