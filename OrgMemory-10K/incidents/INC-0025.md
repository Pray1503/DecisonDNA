# Incident Report: INC-0025 - Cache stampede in fusionerp-core for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0049
* **Linked PR:** PR-0034
* **Linked ADR:** ADR-0009

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-02-14 12:43:00**: System Alert - Anomalous Metrics Detected
- **2021-02-14 12:54:00**: On-call Engineer Acknowledged Alert
- **2021-02-14 14:14:00**: Mitigation Applied - Increased pod count
- **2021-02-14 14:49:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 14:14:00 by rolling back production deployment DEP-0049 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
