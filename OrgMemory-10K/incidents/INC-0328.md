# Incident Report: INC-0328 - Out of memory (OOM) crash in fusionerp-frontend pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0682
* **Linked PR:** PR-0343
* **Linked ADR:** ADR-0082

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2022-01-03 11:56:00**: System Alert - Anomalous Metrics Detected
- **2022-01-03 12:09:00**: On-call Engineer Acknowledged Alert
- **2022-01-03 13:12:00**: Mitigation Applied - Increased pod count
- **2022-01-03 15:35:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 13:12:00 by rolling back production deployment DEP-0682 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
