# Incident Report: INC-0358 - Cache stampede in cloudsync-desktop for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0746
* **Linked PR:** PR-0374
* **Linked ADR:** ADR-0092

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-28 23:00:00**: System Alert - Anomalous Metrics Detected
- **2022-01-28 23:11:00**: On-call Engineer Acknowledged Alert
- **2022-01-29 00:24:00**: Mitigation Applied - Rolled back deployment
- **2022-01-29 01:56:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 00:24:00 by rolling back production deployment DEP-0746 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
