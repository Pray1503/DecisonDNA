# Incident Report: INC-0197 - Message lag spike on Kafka partition for fusionerp-payroll

* **Severity:** P1
* **Linked Deployment:** DEP-0411
* **Linked PR:** PR-0213
* **Linked ADR:** None

## Root Cause Summary
A slow consumer thread due to synchronous downstream HTTP calls. As partition size grew, processing fell behind by over 50,000 messages, delaying order processing in NovaCommerce.

## Incident Timeline
- **2021-08-27 01:18:00**: System Alert - Anomalous Metrics Detected
- **2021-08-27 01:28:00**: On-call Engineer Acknowledged Alert
- **2021-08-27 02:39:00**: Mitigation Applied - Flushed cache
- **2021-08-27 03:26:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 02:39:00 by rolling back production deployment DEP-0411 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement worker pool concurrency in consumer code, wrap calls in circuit breakers, and monitor consumer lag metrics to trigger auto-scaling.
