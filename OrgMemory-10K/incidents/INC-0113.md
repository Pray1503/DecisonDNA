# Incident Report: INC-0113 - Message lag spike on Kafka partition for fusionerp-frontend

* **Severity:** P1
* **Linked Deployment:** DEP-0237
* **Linked PR:** PR-0125
* **Linked ADR:** ADR-0028

## Root Cause Summary
A slow consumer thread due to synchronous downstream HTTP calls. As partition size grew, processing fell behind by over 50,000 messages, delaying order processing in NovaCommerce.

## Incident Timeline
- **2021-05-09 20:30:00**: System Alert - Anomalous Metrics Detected
- **2021-05-09 20:33:00**: On-call Engineer Acknowledged Alert
- **2021-05-09 21:14:00**: Mitigation Applied - Increased pod count
- **2021-05-09 23:50:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 21:14:00 by rolling back production deployment DEP-0237 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement worker pool concurrency in consumer code, wrap calls in circuit breakers, and monitor consumer lag metrics to trigger auto-scaling.
