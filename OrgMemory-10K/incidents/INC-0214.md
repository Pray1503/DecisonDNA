# Incident Report: INC-0214 - Cache stampede in visionai-inference for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0446
* **Linked PR:** PR-0228
* **Linked ADR:** ADR-0058

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-09-12 13:59:00**: System Alert - Anomalous Metrics Detected
- **2021-09-12 14:13:00**: On-call Engineer Acknowledged Alert
- **2021-09-12 15:25:00**: Mitigation Applied - Flushed cache
- **2021-09-12 19:08:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 15:25:00 by rolling back production deployment DEP-0446 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
