# Incident Report: INC-0323 - Cache stampede in visionai-training for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0672
* **Linked PR:** PR-0340
* **Linked ADR:** ADR-0085

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-01 11:46:00**: System Alert - Anomalous Metrics Detected
- **2022-01-01 11:51:00**: On-call Engineer Acknowledged Alert
- **2022-01-01 12:26:00**: Mitigation Applied - Rolled back deployment
- **2022-01-01 16:18:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 12:26:00 by rolling back production deployment DEP-0672 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
