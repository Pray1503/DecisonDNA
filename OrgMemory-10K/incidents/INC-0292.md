# Incident Report: INC-0292 - Cache stampede in devops-ci-cd for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0605
* **Linked PR:** PR-0302
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-11-29 16:37:00**: System Alert - Anomalous Metrics Detected
- **2021-11-29 16:45:00**: On-call Engineer Acknowledged Alert
- **2021-11-29 17:31:00**: Mitigation Applied - Rolled back deployment
- **2021-11-29 19:19:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 17:31:00 by rolling back production deployment DEP-0605 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
