# Incident Report: INC-0170 - Cache stampede in insightcrm-analytics for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0357
* **Linked PR:** PR-0164
* **Linked ADR:** ADR-0041

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-07-27 04:34:00**: System Alert - Anomalous Metrics Detected
- **2021-07-27 04:37:00**: On-call Engineer Acknowledged Alert
- **2021-07-27 05:12:00**: Mitigation Applied - Increased pod count
- **2021-07-27 07:41:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 05:12:00 by rolling back production deployment DEP-0357 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
