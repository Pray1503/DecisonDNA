# Incident Report: INC-0006 - Out of memory (OOM) crash in cloudsync-desktop pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0013
* **Linked PR:** PR-0005
* **Linked ADR:** None

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-01-24 18:27:00**: System Alert - Anomalous Metrics Detected
- **2021-01-24 18:31:00**: On-call Engineer Acknowledged Alert
- **2021-01-24 18:58:00**: Mitigation Applied - Flushed cache
- **2021-01-24 22:14:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 18:58:00 by rolling back production deployment DEP-0013 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
