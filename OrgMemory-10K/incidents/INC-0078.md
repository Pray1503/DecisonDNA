# Incident Report: INC-0078 - Cache stampede in fusionerp-frontend for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0163
* **Linked PR:** PR-0083
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-04-03 21:53:00**: System Alert - Anomalous Metrics Detected
- **2021-04-03 22:01:00**: On-call Engineer Acknowledged Alert
- **2021-04-03 22:33:00**: Mitigation Applied - Rolled back deployment
- **2021-04-04 00:03:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 22:33:00 by rolling back production deployment DEP-0163 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
