# Incident Report: INC-0331 - Cache stampede in platform-k8s-mesh for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0690
* **Linked PR:** PR-0360
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-08 16:00:00**: System Alert - Anomalous Metrics Detected
- **2022-01-08 16:05:00**: On-call Engineer Acknowledged Alert
- **2022-01-08 16:49:00**: Mitigation Applied - Increased pod count
- **2022-01-08 18:52:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 16:49:00 by rolling back production deployment DEP-0690 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
