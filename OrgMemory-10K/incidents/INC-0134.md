# Incident Report: INC-0134 - Unoptimized query on fusionerp-frontend database after release

* **Severity:** P2
* **Linked Deployment:** DEP-0282
* **Linked PR:** PR-0120
* **Linked ADR:** ADR-0028

## Root Cause Summary
A new feature did a sequential scan on a table containing 10M+ rows because the foreign key index was omitted in the migration script. CPU spiked to 100% and query latency went from 5ms to 8000ms.

## Incident Timeline
- **2021-05-29 22:26:00**: System Alert - Anomalous Metrics Detected
- **2021-05-29 22:36:00**: On-call Engineer Acknowledged Alert
- **2021-05-29 23:49:00**: Mitigation Applied - Rolled back deployment
- **2021-05-30 03:49:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 23:49:00 by rolling back production deployment DEP-0282 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Require explain-plan checks in CI/CD pipelines for any new migration files. Enforce indexing guidelines for foreign keys.
