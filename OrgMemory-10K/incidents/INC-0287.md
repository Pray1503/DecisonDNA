# Incident Report: INC-0287 - Cache stampede in fusionerp-core for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0594
* **Linked PR:** PR-0304
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-11-27 08:56:00**: System Alert - Anomalous Metrics Detected
- **2021-11-27 09:04:00**: On-call Engineer Acknowledged Alert
- **2021-11-27 10:16:00**: Mitigation Applied - Flushed cache
- **2021-11-27 10:57:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 10:16:00 by rolling back production deployment DEP-0594 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
