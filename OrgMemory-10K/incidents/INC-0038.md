# Incident Report: INC-0038 - Unoptimized query on fusionerp-payroll database after release

* **Severity:** P2
* **Linked Deployment:** DEP-0083
* **Linked PR:** PR-0038
* **Linked ADR:** ADR-0008

## Root Cause Summary
A new feature did a sequential scan on a table containing 10M+ rows because the foreign key index was omitted in the migration script. CPU spiked to 100% and query latency went from 5ms to 8000ms.

## Incident Timeline
- **2021-02-24 18:23:00**: System Alert - Anomalous Metrics Detected
- **2021-02-24 18:36:00**: On-call Engineer Acknowledged Alert
- **2021-02-24 20:03:00**: Mitigation Applied - Increased pod count
- **2021-02-24 22:31:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 20:03:00 by rolling back production deployment DEP-0083 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Require explain-plan checks in CI/CD pipelines for any new migration files. Enforce indexing guidelines for foreign keys.
