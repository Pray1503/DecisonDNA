# Incident Report: INC-0208 - Cache stampede in devops-ci-cd for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0432
* **Linked PR:** PR-0222
* **Linked ADR:** ADR-0057

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-09-04 17:06:00**: System Alert - Anomalous Metrics Detected
- **2021-09-04 17:09:00**: On-call Engineer Acknowledged Alert
- **2021-09-04 18:16:00**: Mitigation Applied - Rolled back deployment
- **2021-09-04 21:39:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 18:16:00 by rolling back production deployment DEP-0432 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
