# Incident Report: INC-0278 - Cache stampede in platform-k8s-mesh for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0576
* **Linked PR:** PR-0284
* **Linked ADR:** ADR-0068

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-11-15 12:14:00**: System Alert - Anomalous Metrics Detected
- **2021-11-15 12:23:00**: On-call Engineer Acknowledged Alert
- **2021-11-15 13:07:00**: Mitigation Applied - Increased pod count
- **2021-11-15 13:59:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 13:07:00 by rolling back production deployment DEP-0576 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
