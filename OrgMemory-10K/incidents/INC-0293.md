# Incident Report: INC-0293 - Out of memory (OOM) crash in security-auth-proxy pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0607
* **Linked PR:** PR-0278
* **Linked ADR:** ADR-0069

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-11-30 15:20:00**: System Alert - Anomalous Metrics Detected
- **2021-11-30 15:26:00**: On-call Engineer Acknowledged Alert
- **2021-11-30 16:45:00**: Mitigation Applied - Flushed cache
- **2021-11-30 18:38:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 16:45:00 by rolling back production deployment DEP-0607 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
