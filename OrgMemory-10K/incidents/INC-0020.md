# Incident Report: INC-0020 - Database connection pool exhaustion on visionai-inference

* **Severity:** P0
* **Linked Deployment:** DEP-0045
* **Linked PR:** PR-0030
* **Linked ADR:** ADR-0007

## Root Cause Summary
The service connection pool size was set to 20, but under heavy concurrent traffic, queries blocked on database, causing requests to queue up and exhaust all worker threads. The health check endpoint also blocked, leading Kubernetes to restart pods in a loop.

## Incident Timeline
- **2021-02-11 15:47:00**: System Alert - Anomalous Metrics Detected
- **2021-02-11 15:55:00**: On-call Engineer Acknowledged Alert
- **2021-02-11 17:15:00**: Mitigation Applied - Flushed cache
- **2021-02-11 18:37:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 17:15:00 by rolling back production deployment DEP-0045 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
We must decoupled health check endpoints from primary database checks (make them shallow), increase connection pool limits, and implement rate limiting on expensive endpoints.
