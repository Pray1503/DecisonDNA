# Incident Report: INC-0186 - Out of memory (OOM) crash in atlaspay-portal pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0389
* **Linked PR:** PR-0178
* **Linked ADR:** ADR-0045

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-08-12 03:27:00**: System Alert - Anomalous Metrics Detected
- **2021-08-12 03:34:00**: On-call Engineer Acknowledged Alert
- **2021-08-12 04:29:00**: Mitigation Applied - Flushed cache
- **2021-08-12 05:14:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 04:29:00 by rolling back production deployment DEP-0389 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
