# Incident Report: INC-0106 - Out of memory (OOM) crash in fusionerp-payroll pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0222
* **Linked PR:** PR-0117
* **Linked ADR:** ADR-0027

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-05-03 20:07:00**: System Alert - Anomalous Metrics Detected
- **2021-05-03 20:18:00**: On-call Engineer Acknowledged Alert
- **2021-05-03 21:33:00**: Mitigation Applied - Rolled back deployment
- **2021-05-04 01:08:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 21:33:00 by rolling back production deployment DEP-0222 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
