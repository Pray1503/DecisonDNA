# Incident Report: INC-0036 - Message lag spike on Kafka partition for cloudsync-daemon

* **Severity:** P1
* **Linked Deployment:** DEP-0077
* **Linked PR:** PR-0042
* **Linked ADR:** ADR-0010

## Root Cause Summary
A slow consumer thread due to synchronous downstream HTTP calls. As partition size grew, processing fell behind by over 50,000 messages, delaying order processing in NovaCommerce.

## Incident Timeline
- **2021-02-20 00:26:00**: System Alert - Anomalous Metrics Detected
- **2021-02-20 00:41:00**: On-call Engineer Acknowledged Alert
- **2021-02-20 01:12:00**: Mitigation Applied - Flushed cache
- **2021-02-20 03:33:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 01:12:00 by rolling back production deployment DEP-0077 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement worker pool concurrency in consumer code, wrap calls in circuit breakers, and monitor consumer lag metrics to trigger auto-scaling.
