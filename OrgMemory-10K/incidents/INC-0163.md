# Incident Report: INC-0163 - Cache stampede in insightcrm-analytics for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0342
* **Linked PR:** PR-0170
* **Linked ADR:** ADR-0041

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-07-13 22:12:00**: System Alert - Anomalous Metrics Detected
- **2021-07-13 22:26:00**: On-call Engineer Acknowledged Alert
- **2021-07-13 22:46:00**: Mitigation Applied - Flushed cache
- **2021-07-14 00:05:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 22:46:00 by rolling back production deployment DEP-0342 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
