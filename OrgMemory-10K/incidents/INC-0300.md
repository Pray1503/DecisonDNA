# Incident Report: INC-0300 - Cache stampede in platform-monitoring for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0622
* **Linked PR:** PR-0313
* **Linked ADR:** ADR-0077

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-12-09 15:48:00**: System Alert - Anomalous Metrics Detected
- **2021-12-09 15:52:00**: On-call Engineer Acknowledged Alert
- **2021-12-09 16:37:00**: Mitigation Applied - Flushed cache
- **2021-12-09 19:15:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 16:37:00 by rolling back production deployment DEP-0622 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
