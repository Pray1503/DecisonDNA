# Incident Report: INC-0092 - Cache stampede in security-scanner for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0192
* **Linked PR:** PR-0078
* **Linked ADR:** ADR-0019

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-04-18 03:08:00**: System Alert - Anomalous Metrics Detected
- **2021-04-18 03:12:00**: On-call Engineer Acknowledged Alert
- **2021-04-18 04:37:00**: Mitigation Applied - Rolled back deployment
- **2021-04-18 07:19:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 04:37:00 by rolling back production deployment DEP-0192 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
