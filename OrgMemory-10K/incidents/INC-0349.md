# Incident Report: INC-0349 - Cache stampede in fusionerp-payroll for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0729
* **Linked PR:** PR-0371
* **Linked ADR:** ADR-0089

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-20 02:31:00**: System Alert - Anomalous Metrics Detected
- **2022-01-20 02:36:00**: On-call Engineer Acknowledged Alert
- **2022-01-20 03:41:00**: Mitigation Applied - Rolled back deployment
- **2022-01-20 06:46:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 03:41:00 by rolling back production deployment DEP-0729 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
