# Incident Report: INC-0150 - Cache stampede in cloudsync-storage for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0314
* **Linked PR:** PR-0145
* **Linked ADR:** ADR-0035

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-06-21 07:40:00**: System Alert - Anomalous Metrics Detected
- **2021-06-21 07:42:00**: On-call Engineer Acknowledged Alert
- **2021-06-21 08:05:00**: Mitigation Applied - Rolled back deployment
- **2021-06-21 11:17:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 08:05:00 by rolling back production deployment DEP-0314 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
