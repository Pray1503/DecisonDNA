# Incident Report: INC-0127 - Cache stampede in novacommerce-cart for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0265
* **Linked PR:** PR-0138
* **Linked ADR:** ADR-0033

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-05-22 01:47:00**: System Alert - Anomalous Metrics Detected
- **2021-05-22 01:59:00**: On-call Engineer Acknowledged Alert
- **2021-05-22 02:29:00**: Mitigation Applied - Flushed cache
- **2021-05-22 04:31:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 02:29:00 by rolling back production deployment DEP-0265 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
