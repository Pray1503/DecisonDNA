# Incident Report: INC-0175 - Out of memory (OOM) crash in security-scanner pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0369
* **Linked PR:** PR-0188
* **Linked ADR:** ADR-0047

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-07-30 15:18:00**: System Alert - Anomalous Metrics Detected
- **2021-07-30 15:23:00**: On-call Engineer Acknowledged Alert
- **2021-07-30 16:26:00**: Mitigation Applied - Rolled back deployment
- **2021-07-30 18:05:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 16:26:00 by rolling back production deployment DEP-0369 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
