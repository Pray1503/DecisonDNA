# Incident Report: INC-0044 - Out of memory (OOM) crash in security-auth-proxy pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0094
* **Linked PR:** PR-0024
* **Linked ADR:** ADR-0006

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-03-02 07:37:00**: System Alert - Anomalous Metrics Detected
- **2021-03-02 07:42:00**: On-call Engineer Acknowledged Alert
- **2021-03-02 09:12:00**: Mitigation Applied - Flushed cache
- **2021-03-02 10:15:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 09:12:00 by rolling back production deployment DEP-0094 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
