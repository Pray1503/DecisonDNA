# Incident Report: INC-0041 - Out of memory (OOM) crash in cloudsync-storage pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0088
* **Linked PR:** PR-0044
* **Linked ADR:** ADR-0012

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-02-27 22:14:00**: System Alert - Anomalous Metrics Detected
- **2021-02-27 22:25:00**: On-call Engineer Acknowledged Alert
- **2021-02-27 23:02:00**: Mitigation Applied - Increased pod count
- **2021-02-28 01:40:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 23:02:00 by rolling back production deployment DEP-0088 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
