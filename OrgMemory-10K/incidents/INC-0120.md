# Incident Report: INC-0120 - Out of memory (OOM) crash in visionai-training pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0251
* **Linked PR:** PR-0104
* **Linked ADR:** ADR-0024

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-05-15 15:09:00**: System Alert - Anomalous Metrics Detected
- **2021-05-15 15:20:00**: On-call Engineer Acknowledged Alert
- **2021-05-15 15:36:00**: Mitigation Applied - Rolled back deployment
- **2021-05-15 17:50:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 15:36:00 by rolling back production deployment DEP-0251 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
