# Incident Report: INC-0026 - Routing loop in Istio service mesh for fusionerp-core

* **Severity:** P0
* **Linked Deployment:** DEP-0051
* **Linked PR:** PR-0036
* **Linked ADR:** ADR-0009

## Root Cause Summary
A misconfigured VirtualService manifest in Terraform caused traffic to cycle between the canary deployment and the main service. Latency spiked and error rates reached 100% due to maximum hop recursion.

## Incident Timeline
- **2021-02-15 00:45:00**: System Alert - Anomalous Metrics Detected
- **2021-02-15 00:49:00**: On-call Engineer Acknowledged Alert
- **2021-02-15 02:06:00**: Mitigation Applied - Rolled back deployment
- **2021-02-15 05:57:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 02:06:00 by rolling back production deployment DEP-0051 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Add deployment linting checks for mesh configurations. Implement dry-run verification steps in CI/CD pipeline before applying mesh routes.
