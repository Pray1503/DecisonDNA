# Incident Report: INC-0276 - Database connection pool exhaustion on insightcrm-api

* **Severity:** P0
* **Linked Deployment:** DEP-0572
* **Linked PR:** PR-0291
* **Linked ADR:** ADR-0071

## Root Cause Summary
The service connection pool size was set to 20, but under heavy concurrent traffic, queries blocked on MongoDB, causing requests to queue up and exhaust all worker threads. The health check endpoint also blocked, leading Kubernetes to restart pods in a loop.

## Incident Timeline
- **2021-11-13 10:13:00**: System Alert - Anomalous Metrics Detected
- **2021-11-13 10:17:00**: On-call Engineer Acknowledged Alert
- **2021-11-13 11:46:00**: Mitigation Applied - Flushed cache
- **2021-11-13 15:10:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 11:46:00 by rolling back production deployment DEP-0572 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
We must decoupled health check endpoints from primary database checks (make them shallow), increase connection pool limits, and implement rate limiting on expensive endpoints.
