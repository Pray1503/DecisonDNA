# Incident Report: INC-0118 - Out of memory (OOM) crash in platform-logging pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0247
* **Linked PR:** PR-0102
* **Linked ADR:** ADR-0023

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2021-05-13 05:01:00**: System Alert - Anomalous Metrics Detected
- **2021-05-13 05:15:00**: On-call Engineer Acknowledged Alert
- **2021-05-13 06:32:00**: Mitigation Applied - Increased pod count
- **2021-05-13 09:37:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 06:32:00 by rolling back production deployment DEP-0247 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
