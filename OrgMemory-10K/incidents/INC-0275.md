# Incident Report: INC-0275 - Cache stampede in security-auth-proxy for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0570
* **Linked PR:** PR-0290
* **Linked ADR:** ADR-0069

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-11-12 20:09:00**: System Alert - Anomalous Metrics Detected
- **2021-11-12 20:14:00**: On-call Engineer Acknowledged Alert
- **2021-11-12 20:51:00**: Mitigation Applied - Increased pod count
- **2021-11-12 22:30:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 20:51:00 by rolling back production deployment DEP-0570 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
