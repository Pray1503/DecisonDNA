# Incident Report: INC-0345 - Out of memory (OOM) crash in novacommerce-checkout pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0719
* **Linked PR:** PR-0355
* **Linked ADR:** ADR-0086

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (1Gi) and got OOMKilled.

## Incident Timeline
- **2022-01-17 10:08:00**: System Alert - Anomalous Metrics Detected
- **2022-01-17 10:19:00**: On-call Engineer Acknowledged Alert
- **2022-01-17 11:05:00**: Mitigation Applied - Increased pod count
- **2022-01-17 12:12:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 11:05:00 by rolling back production deployment DEP-0719 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
