# Incident Report: INC-0280 - Cache stampede in cloudsync-daemon for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0580
* **Linked PR:** PR-0294
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-11-17 17:37:00**: System Alert - Anomalous Metrics Detected
- **2021-11-17 17:42:00**: On-call Engineer Acknowledged Alert
- **2021-11-17 18:57:00**: Mitigation Applied - Increased pod count
- **2021-11-17 22:10:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 18:57:00 by rolling back production deployment DEP-0580 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
