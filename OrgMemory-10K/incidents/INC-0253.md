# Incident Report: INC-0253 - Cache stampede in platform-monitoring for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0523
* **Linked PR:** PR-0259
* **Linked ADR:** ADR-0065

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-10-22 22:37:00**: System Alert - Anomalous Metrics Detected
- **2021-10-22 22:50:00**: On-call Engineer Acknowledged Alert
- **2021-10-22 23:06:00**: Mitigation Applied - Flushed cache
- **2021-10-23 01:19:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 23:06:00 by rolling back production deployment DEP-0523 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
