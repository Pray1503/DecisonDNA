# Incident Report: INC-0337 - Cache stampede in fusionerp-payroll for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0700
* **Linked PR:** PR-0358
* **Linked ADR:** ADR-0089

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-12 20:40:00**: System Alert - Anomalous Metrics Detected
- **2022-01-12 20:55:00**: On-call Engineer Acknowledged Alert
- **2022-01-12 21:26:00**: Mitigation Applied - Increased pod count
- **2022-01-13 00:37:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 21:26:00 by rolling back production deployment DEP-0700 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
