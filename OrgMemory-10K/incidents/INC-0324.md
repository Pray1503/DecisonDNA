# Incident Report: INC-0324 - Cache stampede in visionai-training for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0674
* **Linked PR:** PR-0344
* **Linked ADR:** ADR-0083

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-01 18:31:00**: System Alert - Anomalous Metrics Detected
- **2022-01-01 18:36:00**: On-call Engineer Acknowledged Alert
- **2022-01-01 19:16:00**: Mitigation Applied - Flushed cache
- **2022-01-01 21:50:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 19:16:00 by rolling back production deployment DEP-0674 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
