# Incident Report: INC-0112 - Cache stampede in fusionerp-payroll for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0233
* **Linked PR:** PR-0118
* **Linked ADR:** ADR-0027

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-05-09 13:15:00**: System Alert - Anomalous Metrics Detected
- **2021-05-09 13:28:00**: On-call Engineer Acknowledged Alert
- **2021-05-09 14:43:00**: Mitigation Applied - Increased pod count
- **2021-05-09 15:18:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 14:43:00 by rolling back production deployment DEP-0233 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
