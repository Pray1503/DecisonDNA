# Incident Report: INC-0146 - Cache stampede in atlaspay-portal for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0308
* **Linked PR:** PR-0142
* **Linked ADR:** ADR-0034

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-06-18 16:10:00**: System Alert - Anomalous Metrics Detected
- **2021-06-18 16:17:00**: On-call Engineer Acknowledged Alert
- **2021-06-18 17:39:00**: Mitigation Applied - Flushed cache
- **2021-06-18 18:30:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 17:39:00 by rolling back production deployment DEP-0308 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
