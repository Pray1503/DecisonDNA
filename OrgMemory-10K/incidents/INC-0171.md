# Incident Report: INC-0171 - Cache stampede in security-auth-proxy for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0359
* **Linked PR:** PR-0183
* **Linked ADR:** ADR-0046

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-07-27 09:03:00**: System Alert - Anomalous Metrics Detected
- **2021-07-27 09:07:00**: On-call Engineer Acknowledged Alert
- **2021-07-27 10:00:00**: Mitigation Applied - Flushed cache
- **2021-07-27 12:31:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 10:00:00 by rolling back production deployment DEP-0359 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
