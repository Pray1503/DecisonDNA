# Incident Report: INC-0189 - Cache stampede in novacommerce-ui for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0395
* **Linked PR:** PR-0195
* **Linked ADR:** ADR-0050

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-08-18 00:11:00**: System Alert - Anomalous Metrics Detected
- **2021-08-18 00:15:00**: On-call Engineer Acknowledged Alert
- **2021-08-18 01:23:00**: Mitigation Applied - Rolled back deployment
- **2021-08-18 05:10:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 01:23:00 by rolling back production deployment DEP-0395 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
