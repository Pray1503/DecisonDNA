# Incident Report: INC-0219 - Cache stampede in platform-logging for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0456
* **Linked PR:** PR-0234
* **Linked ADR:** ADR-0060

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-09-16 13:22:00**: System Alert - Anomalous Metrics Detected
- **2021-09-16 13:26:00**: On-call Engineer Acknowledged Alert
- **2021-09-16 13:45:00**: Mitigation Applied - Flushed cache
- **2021-09-16 14:51:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 13:45:00 by rolling back production deployment DEP-0456 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
