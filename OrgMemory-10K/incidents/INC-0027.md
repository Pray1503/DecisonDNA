# Incident Report: INC-0027 - Cache stampede in fusionerp-payroll for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0055
* **Linked PR:** PR-0028
* **Linked ADR:** None

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-02-15 06:43:00**: System Alert - Anomalous Metrics Detected
- **2021-02-15 06:56:00**: On-call Engineer Acknowledged Alert
- **2021-02-15 08:13:00**: Mitigation Applied - Flushed cache
- **2021-02-15 10:03:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 08:13:00 by rolling back production deployment DEP-0055 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
