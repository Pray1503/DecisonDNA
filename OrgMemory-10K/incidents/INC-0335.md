# Incident Report: INC-0335 - Cache stampede in novacommerce-cart for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0694
* **Linked PR:** PR-0324
* **Linked ADR:** ADR-0078

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2022-01-10 08:52:00**: System Alert - Anomalous Metrics Detected
- **2022-01-10 09:07:00**: On-call Engineer Acknowledged Alert
- **2022-01-10 09:39:00**: Mitigation Applied - Flushed cache
- **2022-01-10 10:15:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 09:39:00 by rolling back production deployment DEP-0694 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
