# Incident Report: INC-0089 - Out of memory (OOM) crash in fusionerp-payroll pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0183
* **Linked PR:** PR-0096
* **Linked ADR:** ADR-0021

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-04-13 06:27:00**: System Alert - Anomalous Metrics Detected
- **2021-04-13 06:37:00**: On-call Engineer Acknowledged Alert
- **2021-04-13 07:59:00**: Mitigation Applied - Increased pod count
- **2021-04-13 09:05:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 07:59:00 by rolling back production deployment DEP-0183 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
