# Incident Report: INC-0075 - Cache stampede in atlaspay-gateway for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0157
* **Linked PR:** PR-0062
* **Linked ADR:** ADR-0016

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-04-01 21:21:00**: System Alert - Anomalous Metrics Detected
- **2021-04-01 21:31:00**: On-call Engineer Acknowledged Alert
- **2021-04-01 22:39:00**: Mitigation Applied - Increased pod count
- **2021-04-01 23:25:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 22:39:00 by rolling back production deployment DEP-0157 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
