# Incident Report: INC-0071 - Out of memory (OOM) crash in security-scanner pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0149
* **Linked PR:** PR-0080
* **Linked ADR:** ADR-0019

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-03-30 07:20:00**: System Alert - Anomalous Metrics Detected
- **2021-03-30 07:27:00**: On-call Engineer Acknowledged Alert
- **2021-03-30 08:33:00**: Mitigation Applied - Rolled back deployment
- **2021-03-30 09:48:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 08:33:00 by rolling back production deployment DEP-0149 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
