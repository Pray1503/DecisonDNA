# Incident Report: INC-0070 - Out of memory (OOM) crash in security-scanner pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0151
* **Linked PR:** PR-0084
* **Linked ADR:** None

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (1Gi) and got OOMKilled.

## Incident Timeline
- **2021-03-30 05:20:00**: System Alert - Anomalous Metrics Detected
- **2021-03-30 05:32:00**: On-call Engineer Acknowledged Alert
- **2021-03-30 06:46:00**: Mitigation Applied - Flushed cache
- **2021-03-30 07:33:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 06:46:00 by rolling back production deployment DEP-0151 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
