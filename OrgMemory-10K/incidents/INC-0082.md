# Incident Report: INC-0082 - Cache stampede in novacommerce-ui for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0169
* **Linked PR:** PR-0070
* **Linked ADR:** ADR-0017

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-04-06 10:33:00**: System Alert - Anomalous Metrics Detected
- **2021-04-06 10:35:00**: On-call Engineer Acknowledged Alert
- **2021-04-06 11:02:00**: Mitigation Applied - Increased pod count
- **2021-04-06 12:31:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 11:02:00 by rolling back production deployment DEP-0169 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
