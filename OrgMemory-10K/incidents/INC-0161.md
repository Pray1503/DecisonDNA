# Incident Report: INC-0161 - Cache stampede in platform-logging for metadata queries

* **Severity:** P1
* **Linked Deployment:** DEP-0338
* **Linked PR:** PR-0163
* **Linked ADR:** ADR-0039

## Root Cause Summary
An eviction of high-frequency metadata cache keys in Redis occurred concurrently with a traffic spike. Thousands of pods hit the underlying database at once to re-fetch the metadata, locking tables.

## Incident Timeline
- **2021-07-10 08:19:00**: System Alert - Anomalous Metrics Detected
- **2021-07-10 08:26:00**: On-call Engineer Acknowledged Alert
- **2021-07-10 08:48:00**: Mitigation Applied - Rolled back deployment
- **2021-07-10 09:37:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 08:48:00 by rolling back production deployment DEP-0338 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Implement cache key locking/mutexes (single-flight pattern) so only one request updates the cache while others wait. Add jitter to cache TTLs.
