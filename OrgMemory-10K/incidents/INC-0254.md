# Incident Report: INC-0254 - Out of memory (OOM) crash in platform-monitoring pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0528
* **Linked PR:** PR-0260
* **Linked ADR:** ADR-0065

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-10-23 02:08:00**: System Alert - Anomalous Metrics Detected
- **2021-10-23 02:23:00**: On-call Engineer Acknowledged Alert
- **2021-10-23 03:33:00**: Mitigation Applied - Increased pod count
- **2021-10-23 05:34:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 03:33:00 by rolling back production deployment DEP-0528 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
