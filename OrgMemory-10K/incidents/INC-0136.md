# Incident Report: INC-0136 - Out of memory (OOM) crash in atlaspay-portal pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0287
* **Linked PR:** PR-0143
* **Linked ADR:** ADR-0034

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (2Gi) and got OOMKilled.

## Incident Timeline
- **2021-06-01 09:35:00**: System Alert - Anomalous Metrics Detected
- **2021-06-01 09:45:00**: On-call Engineer Acknowledged Alert
- **2021-06-01 10:52:00**: Mitigation Applied - Rolled back deployment
- **2021-06-01 14:08:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 10:52:00 by rolling back production deployment DEP-0287 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
