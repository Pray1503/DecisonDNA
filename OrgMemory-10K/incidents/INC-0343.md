# Incident Report: INC-0343 - Out of memory (OOM) crash in novacommerce-ui pod during batch processing

* **Severity:** P1
* **Linked Deployment:** DEP-0704
* **Linked PR:** PR-0354
* **Linked ADR:** None

## Root Cause Summary
A memory leak in the Go/Python worker loop processing batch uploads. The worker accumulated pointers in a global slice and did not trigger garbage collection timely. Pod reached K8s limit (512Mi) and got OOMKilled.

## Incident Timeline
- **2022-01-14 18:14:00**: System Alert - Anomalous Metrics Detected
- **2022-01-14 18:17:00**: On-call Engineer Acknowledged Alert
- **2022-01-14 18:43:00**: Mitigation Applied - Rolled back deployment
- **2022-01-14 19:17:00**: Incident Resolved - System metrics stabilized

## Resolution Details
Applied mitigation at 18:43:00 by rolling back production deployment DEP-0704 or applying hotfix. Monitored CPU and error rates until they returned to baseline levels.

## Lessons Learned
Profile heap usage during batch tasks, reuse object buffers, and add strict memory limits to K8s configs with warnings at 80% usage.
