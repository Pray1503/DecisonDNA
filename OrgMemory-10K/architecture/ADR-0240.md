# ADR-0240: Adopt MongoDB for atlaspay-portal database storage

* **Status:** Accepted
* **Date:** 2023-07-17
* **Related Project:** PRJ-007
* **Owner:** EMP-148
* **Complexity:** Medium
* **Priority:** Medium
* **Tags:** database, storage, backend

## Context
Our current database strategy for atlaspay-portal is experiencing scalability limitations under peak loads. We need a solution that can handle high throughput, support strong consistency, and scale horizontally.

## Problem
High read/write latency during peak traffic periods resulting in database connection pools exhausting, causing intermittent errors in downstream services.

## Alternatives Considered
1. Scale vertical resources on existing systems.
2. Implement a distributed cache layer (e.g. Redis) as a buffer.
3. Migrate to a multi-master distributed DB like MongoDB.

## Decision
Migrate the primary storage of atlaspay-portal to MongoDB to leverage its native scaling and high availability features.

## Rationale
We chose MongoDB because of its robust clustering capabilities, low latency reads, and strong developer familiarity. It provides the required performance profile and matches our tech stack.

## Consequences
Developers must learn MongoDB-specific query optimization. We must set up migration scripts and operational monitoring for the new clusters.

## Expected Benefits
Reduced query latency by 50%, elimination of connection pool exhaustion incidents, and support for 5x current transaction volume.

## Potential Risks
Complexity of live migration, operational overhead of maintaining clusters, and potential data format conversion issues during the transition.
