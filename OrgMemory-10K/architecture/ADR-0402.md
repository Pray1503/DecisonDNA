# ADR-0402: Implement Redis cache layer for platform-monitoring

* **Status:** Accepted
* **Date:** 2025-02-18
* **Related Project:** PRJ-022
* **Owner:** EMP-159
* **Complexity:** Medium
* **Priority:** Critical
* **Tags:** cache, performance, scaling

## Context
platform-monitoring performs heavy database reads for static or slow-moving configurations, putting unnecessary read load on our primary databases and increasing endpoint latency.

## Problem
High load on databases and slow API responses due to repeated queries for the same static configuration and user profile data.

## Alternatives Considered
1. Add read replicas to the primary database.
2. Use in-memory application caching.
3. Deploy a centralized Redis caching cluster.

## Decision
Implement Redis as a distributed caching layer for platform-monitoring endpoints.

## Rationale
A centralized Redis cluster allows shared cache across all horizontal pods of the service, keeping memory usage clean and providing sub-millisecond lookups.

## Consequences
Cache invalidation logic must be added to all update operations. Cache eviction policies (LRU) must be configured.

## Expected Benefits
Endpoint latency reduced by up to 80%; database read IOPS reduced by 60%.

## Potential Risks
Stale cache read anomalies, cache stampede during cold start, and additional cluster infrastructure costs.
