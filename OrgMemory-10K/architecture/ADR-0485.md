# ADR-0485: Use Kubernetes to deploy novacommerce-ui to AWS

* **Status:** Accepted
* **Date:** 2025-11-12
* **Related Project:** PRJ-002
* **Owner:** EMP-088
* **Complexity:** Medium
* **Priority:** Medium
* **Tags:** deployment, infrastructure, devops

## Context
Our current deployment model using manual VM provisioning is slow, error-prone, and makes scaling applications dynamically very difficult during high load.

## Problem
Deployment takes over 40 minutes, and we lack auto-scaling. Small configuration drift on VMs makes debugging environments difficult.

## Alternatives Considered
1. Script VM creation using custom Ansible and AMI images.
2. Deploy directly to AWS ECS.
3. Implement a complete Kubernetes container orchestration architecture.

## Decision
Standardize all microservice deployments, starting with novacommerce-ui, on Kubernetes hosted on AWS.

## Rationale
Kubernetes provides declarative configuration, auto-healing, and dynamic horizontal pod autoscaling (HPA) natively.

## Consequences
All services must be containerized (Dockerfiles written). Helm charts must be created, and CI/CD pipelines updated.

## Expected Benefits
Deployment time down from 40m to under 5m; auto-scaling responds to traffic load in under 2m.

## Potential Risks
Steep learning curve for the team, complex networking policies, and increased infrastructure cost for the control plane.
