# Decision Memory Object: MEM-0050 (Implement Memcached cache layer for novacommerce-ui)

* **Original ADR:** [ADR-0050](../architecture/ADR-0050.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 0.10 (Scale: 0.0 - 1.0)

## 1. Context and Problem
novacommerce-ui performs heavy database reads for static or slow-moving configurations, putting unnecessary read load on our primary databases and increasing endpoint latency.

* **Problem Statement:** High load on databases and slow API responses due to repeated queries for the same static configuration and user profile data.

## 2. Alternatives Considered
1. Add read replicas to the primary database.
2. Use in-memory application caching.
3. Deploy a centralized Memcached caching cluster.

## 3. Decision & Technical Direction
Implement Memcached as a distributed caching layer for novacommerce-ui endpoints.

## 6. Real-world Performance Impact
Average latency went from 270.02ms to 674.58ms (+404.56 / +149.8%).

## 7. Lessons Learned & Retrospective
Cache invalidation logic must be added to all update operations. Cache eviction policies (LRU) must be configured.
Deployed in DEP-0421. Caused incident INC-0203 due to: Out of memory (OOM) crash in novacommerce-ui pod during batch processing. Rolled back or mitigated.
