# Decision Memory Object: MEM-0065 (Implement Memcached cache layer for platform-monitoring)

* **Original ADR:** [ADR-0065](../architecture/ADR-0065.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 0.10 (Scale: 0.0 - 1.0)

## 1. Context and Problem
platform-monitoring performs heavy database reads for static or slow-moving configurations, putting unnecessary read load on our primary databases and increasing endpoint latency.

* **Problem Statement:** High load on databases and slow API responses due to repeated queries for the same static configuration and user profile data.

## 2. Alternatives Considered
1. Add read replicas to the primary database.
2. Use in-memory application caching.
3. Deploy a centralized Memcached caching cluster.

## 3. Decision & Technical Direction
Implement Memcached as a distributed caching layer for platform-monitoring endpoints.

## 6. Real-world Performance Impact
Average latency went from 34.87ms to 447.93ms (+413.06 / +1184.4%).

## 7. Lessons Learned & Retrospective
Cache invalidation logic must be added to all update operations. Cache eviction policies (LRU) must be configured.
Deployed in DEP-0548. Caused incident INC-0266 due to: Database connection pool exhaustion on platform-monitoring. Rolled back or mitigated.
