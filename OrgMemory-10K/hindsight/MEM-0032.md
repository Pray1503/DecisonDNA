# Decision Memory Object: MEM-0032 (Introduce AWS SQS for decoupled communications in cloudsync-daemon)

* **Original ADR:** [ADR-0032](../architecture/ADR-0032.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 0.30 (Scale: 0.0 - 1.0)

## 1. Context and Problem
Direct HTTP calls between cloudsync-daemon and other services create hard dependencies. When downstream systems are down, transactions fail immediately, causing poor customer experience.

* **Problem Statement:** Tight coupling leads to cascading failures across the backend. We need asynchronous messaging to guarantee eventual consistency and fault tolerance.

## 2. Alternatives Considered
1. Keep synchronous REST APIs but increase timeouts and retry limits.
2. Introduce an HTTP webhook callback system.
3. Deploy AWS SQS as a centralized event broker.

## 3. Decision & Technical Direction
Integrate AWS SQS to enable asynchronous, event-driven communication between cloudsync-daemon and downstream microservices.
