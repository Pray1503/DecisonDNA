# Decision Memory Object: MEM-0114 (Adopt Cassandra for platform-logging database storage)

* **Original ADR:** [ADR-0114](../architecture/ADR-0114.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 1.00 (Scale: 0.0 - 1.0)

## 1. Context and Problem
Our current database strategy for platform-logging is experiencing scalability limitations under peak loads. We need a solution that can handle high throughput, support strong consistency, and scale horizontally.

* **Problem Statement:** High read/write latency during peak traffic periods resulting in database connection pools exhausting, causing intermittent errors in downstream services.

## 2. Alternatives Considered
1. Scale vertical resources on existing systems.
2. Implement a distributed cache layer (e.g. Redis) as a buffer.
3. Migrate to a multi-master distributed DB like Cassandra.

## 3. Decision & Technical Direction
Migrate the primary storage of platform-logging to Cassandra to leverage its native scaling and high availability features.
