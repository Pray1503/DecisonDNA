# Decision Memory Object: MEM-0092 (Introduce Kafka for decoupled communications in cloudsync-desktop)

* **Original ADR:** [ADR-0092](../architecture/ADR-0092.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 0.70 (Scale: 0.0 - 1.0)

## 1. Context and Problem
Direct HTTP calls between cloudsync-desktop and other services create hard dependencies. When downstream systems are down, transactions fail immediately, causing poor customer experience.

* **Problem Statement:** Tight coupling leads to cascading failures across the backend. We need asynchronous messaging to guarantee eventual consistency and fault tolerance.

## 2. Alternatives Considered
1. Keep synchronous REST APIs but increase timeouts and retry limits.
2. Introduce an HTTP webhook callback system.
3. Deploy Kafka as a centralized event broker.

## 3. Decision & Technical Direction
Integrate Kafka to enable asynchronous, event-driven communication between cloudsync-desktop and downstream microservices.
