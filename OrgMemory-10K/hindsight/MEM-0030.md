# Decision Memory Object: MEM-0030 (Implement Memcached cache layer for insightcrm-analytics)

* **Original ADR:** [ADR-0030](../architecture/ADR-0030.md)
* **Status:** Accepted
* **Memory Version:** v1.0.0
* **Operational Confidence Score:** 0.60 (Scale: 0.0 - 1.0)

## 1. Context and Problem
insightcrm-analytics performs heavy database reads for static or slow-moving configurations, putting unnecessary read load on our primary databases and increasing endpoint latency.

* **Problem Statement:** High load on databases and slow API responses due to repeated queries for the same static configuration and user profile data.

## 2. Alternatives Considered
1. Add read replicas to the primary database.
2. Use in-memory application caching.
3. Deploy a centralized Memcached caching cluster.

## 3. Decision & Technical Direction
Implement Memcached as a distributed caching layer for insightcrm-analytics endpoints.

## 6. Real-world Performance Impact
Average latency went from 151.25ms to 403.47ms (+252.22 / +166.8%).

## 7. Lessons Learned & Retrospective
Cache invalidation logic must be added to all update operations. Cache eviction policies (LRU) must be configured.
Deployed in DEP-0291. Caused incident INC-0138 due to: Cache stampede in insightcrm-analytics for metadata queries. Rolled back or mitigated.
